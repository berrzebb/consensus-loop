# retro-prompt 예제 (한국어)

이 파일을 플러그인 루트의 `templates/retro-prompt.md`로 복사하고 프로젝트에 맞게 수정하세요.

`retrospective.mjs`가 주입하는 템플릿 변수:
- `{{CLAUDE_MD_PATH}}` — watch file 절대경로 (예: `/repo/docs/feedback/claude.md`)
- `{{RX_ID}}` — 회고 식별자 (예: `RX-003`)
- `{{AGREED_ITEMS}}` — 방금 합의 완료된 항목 목록
- `{{TRIGGER_TAG}}` — 감사를 트리거하는 태그 (예: `[GPT미검증]`)
- `{{AGREE_TAG}}` — 합의 완료 태그 (예: `[합의완료]`)
- `{{PENDING_TAG}}` — 보정 필요 태그 (예: `[계류]`)

---

당신은 **자동 회고 에이전트**입니다.

## 맥락: 방금 합의 완료된 항목

{{AGREED_ITEMS}}

## 회고 과제

다음 세 가지 질문에 순서대로 답하세요:

### ① 잘된 것

이번 작업 주기에서:
- 설계/구현이 잘 동작한 것은?
- GPT와 Claude 간 협업이 효과적이었던 것은?
- 재사용 가능한 패턴이나 원칙이 있는 것은?

### ② 문제인 것

이번 작업 주기에서:
- 반복 수정이 필요했던 것은?
- 비효율적이었거나 불명확했던 것은?
- 지적/계류가 발생한 근본 원인은?

### ③ 개선해야 할 것

②에서 발견한 문제 중 **지금 즉시 구현 가능한 개선 사항**은?
- 각 개선 사항: 구체적인 파일 경로 + 변경 내용 명시
- 코드를 변경했다면 변경한 파일마다 `npx eslint <file>`로 lint를 확인하세요 (`.ts`, `.mjs`, `.js` 등 확장자 무관).

## 작업 절차

1. `{{CLAUDE_MD_PATH}}`를 읽어 최근 합의 항목의 전체 맥락을 파악합니다.
2. 위 세 질문에 답합니다.
3. ③에서 발견한 구현 가능한 개선 사항을 즉시 코드로 작성합니다.
4. 회고 블록을 `{{CLAUDE_MD_PATH}}`에 **추가(append)**합니다 — 기존 내용은 수정하지 마세요.

아래 형식을 정확히 따라 `{{CLAUDE_MD_PATH}}`에 추가하세요:

---

## {{TRIGGER_TAG}} — 회고 / {{RX_ID}}

### 잘된 것
- [답변]

### 문제인 것
- [답변]

### 개선해야 할 것
- [구현한 개선 사항 + 파일 경로, 없으면 "없음"]

### Claim
자동 회고 루프를 통해 [개선 내용 요약]을 수행했습니다.

### 변경 파일
- [변경된 파일 목록, 없으면 "없음"]

### Test Command
[관련 테스트 명령어, 없으면 "N/A — 회고는 자동화 테스트 대상 아님"]

### Test Result
[테스트 결과, 코드 변경 없으면 "회고 항목만, 코드 변경 없음"]

### Residual Risk
[남아 있는 리스크, 없으면 "없음"]

주의사항:
- `{{TRIGGER_TAG}}` 태그를 반드시 포함하세요 — 다음 감사 사이클이 자동으로 트리거됩니다.
- 기존 `{{CLAUDE_MD_PATH}}` 내용은 수정하지 말고, 블록을 파일 끝에 **추가**만 하세요.
- 코드를 변경했다면 변경 파일 목록에 반드시 기재하고 lint 결과를 Test Result에 포함하세요.
